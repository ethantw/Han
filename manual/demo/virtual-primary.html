Virtual Primary <rt> — 可行性示範

驗證：在沒有 1:1 primary 層的多重非注音 <rtc> 情境下， 注入隱藏的「虛擬 primary」後，能否正確輸出 v4 canonical 巢狀 ruby， 且 CSS rt.han-vp { display: none } 是否能讓視覺完全正確。

Case 1 — 邊界相容 ✅

輸入（legacy markup）

<ruby>
  <rb>我</rb><rb>愛</rb><rb>台</rb><rb>灣</rb>
  <rtc lang="en"><rt rbspan="2">I love</rt><rt rbspan="2">Taiwan</rt></rtc>
  <rtc lang="ja"><rt rbspan="4">台湾大好き</rt></rtc>
</ruby>

邊界集合：
  en-rtc  {0, 2, 4}   ← finer（內層）
  ja-rtc  {0, 4}      ← coarser（外層）
  ja-rtc 邊界 ⊆ en-rtc 邊界 → 相容

轉換後輸出（虛擬 primary 已注入）

<!-- rt.han-vp 由 CSS display:none 隱藏 -->
<ruby lang="ja">
  <ruby lang="en">
    <ruby>我<rt class="han-vp" aria-hidden="true"></rt></ruby>
    <ruby>愛<rt class="han-vp" aria-hidden="true"></rt></ruby>
    <rt lang="en">I love</rt>
  </ruby>
  <ruby lang="en">
    <ruby>台<rt class="han-vp" aria-hidden="true"></rt></ruby>
    <ruby>灣<rt class="han-vp" aria-hidden="true"></rt></ruby>
    <rt lang="en">Taiwan</rt>
  </ruby>
  <rt lang="ja">台湾大好き</rt>
</ruby>

渲染結果（此瀏覽器）

我 愛 I love 台 灣 Taiwan 台湾大好き

期望：我愛 上方顯示「I love」；台灣 上方顯示「Taiwan」； 四字整體上方顯示「台湾大好き」。

Case 2 — 三層巢狀「有 1:1 rtc」✅（現有算法即可，不需虛擬 primary）

若作者加入一個 1:1 的 rtc（如拼音），現有 Phase 1 算法直接把它選為 primary， rbspan 層自動成為 extra。這不是虛擬 primary 要解決的問題。 此 case 放在這裡純粹作為視覺對照——Case 1 的虛擬 primary 輸出 應接近此結果，差別只在最內層無拼音 annotation。

輸入（有 1:1 拼音 rtc）

<ruby>
  <rb>我</rb><rb>愛</rb><rb>台</rb><rb>灣</rb>
  <rtc><rt>wǒ</rt><rt>ài</rt><rt>tái</rt><rt>wān</rt></rtc>  <!-- 1:1 → primary -->
  <rtc lang="en"><rt rbspan="2">I love</rt><rt rbspan="2">Taiwan</rt></rtc>
  <rtc lang="ja"><rt rbspan="4">台湾大好き</rt></rtc>
</ruby>

現有算法處理：拼音 rtc 為 primary；en/ja 為 extra（不動任何程式碼）。

渲染結果

我wǒ 愛ài I love 台tái 灣wān Taiwan 台湾大好き

Case 3 — 邊界不相容 ❌（仍需拋錯）

<ruby>
  <rb>A</rb><rb>B</rb><rb>C</rb><rb>D</rb>
  <rtc><rt rbspan="3">ABC</rt><rt>D</rt></rtc>   <!-- 邊界 {0,3,4} -->
  <rtc><rt rbspan="2">AB</rt><rt rbspan="2">CD</rt></rtc> <!-- 邊界 {0,2,4} -->
</ruby>

邊界集合：
  rtc1  {0, 3, 4}
  rtc2  {0, 2, 4}

{0,3,4} ⊄ {0,2,4}（3 不在後者）
{0,2,4} ⊄ {0,3,4}（2 不在前者）
→ 不相容，無法巢狀，拋錯仍是正確行為。

可行性摘要

問題結論
rt.han-vp { display:none } 是否能完全隱藏 annotation？ ✅ 是。display:none 移除整個 annotation box，不佔空間，不影響 line-height。
外層 <ruby> 的 <rt> 是否能橫跨多個內層 ruby？ ⚠️ 取決於瀏覽器。Chromium / Safari 支援；Firefox 對複雜巢狀 ruby 有 layout bug（參見 bug #1823993）。
Accessibility：rt.han-vp 是否對 screen reader 無害？ ✅ display:none + aria-hidden="true" 雙重保險，AT 不讀出。
邊界不相容的 case 是否仍需拋錯？ ✅ 是。虛擬 primary 不能解決邊界衝突；此情況繼續拋錯。
han.css 需要加入什麼？ rt.han-vp { display: none } 一行（或等效規則）。
整體評估 技術上可行，前提是邊界相容且瀏覽器支援巢狀 ruby layout（Chromium / Safari OK）。 Firefox 的 ruby 巢狀 bug 是主要風險點，需進一步測試。

此頁面為 han-stock/next 開發示範，CSS 中 rt.han-vp { display: none } 已直接內嵌於 <style>，模擬 han.css 提供該規則的效果。
