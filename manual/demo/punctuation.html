標點細修工作台

refinePunctuation 與它的同伴 pass 到底產出什麼標記，CSS 又憑什麼 分支。這頁不呼叫 han.auto：每一份樣本自己跑一次 pass，模式寫在 它自己身上，所以四種模式可以並排。控制台的紅色開關會重跑 JS，其餘只動 cascade——分野本身就是這套設計的主張。

紅色 ＝ 重跑 pass；其餘只改 cascade 變數，DOM 一個字都不動。

一、四種模式產出什麼

四份相同的文字，各自以 refinePunctuationWithMode(mode)(el) 跑一次——不受控制台的模式開關影響。這也是「模式可以逐段不同」的證明：該函式 把宣告寫成元素的行內 --han-punctuation-refinement，CSS 的 @container style() 就逐子樹分支。勾「顯示產出標記」看標記。 樣本裡的 。」， 是一串寫在 DOM 裡的連續標點——那是 data-consecutive-pos 的用武之地，而 <q> 生的 括號永遠不在裡面。

auto — 擠壓＋懸掛，一趟走完

她說「今天真好。」，又問明天呢。

    

    

      
compress — 只包，不懸掛

      
她說「今天真好。」，又問明天呢。

      

    

    

      
hang — 只包可懸掛的那幾顆

      
她說「今天真好。」，又問明天呢。

      

    

    

      
none — 原樣送出

      
她說「今天真好。」，又問明天呢。

      

    

  







  
二、cascade 派工與引擎降級

  

    refinePunctuation(el)（不帶模式）讀 cascade 宣告的模式，再依
    引擎能力挑實際要跑的配方：宣告 auto 而引擎原生支援
    text-spacing-trim: trim-start 時，擠壓那半交給引擎，JS 只做懸掛
    ——但它知道作者要的是 auto，所以仍會把每顆可懸掛標點前面
    那顆擠壓者一併包起來，補回原子盒打斷的半個字。下面這份跟著控制台的模式走。
  

  

    

      
她說今天真好、又補了一句明天也會、就走了。

      

    

    

  







  
三、標記契約

  

    pass 產出的每一種包裹與屬性。數字是本頁當下的實際計數，隨控制台變動。
  

  

    
他在 2026 年讀了 Acta Taisolis Sinensis，也讀了《太陽中文報》。

    

  

  

    上面這份同時踩到三件事：漢字與拉丁／數字的接縫（<h-iss>，
    把「混排間隙」切到 strict 或 insert 才會長出來，
    normal 是交給引擎的 text-autospace）、寫死在 DOM 裡的
    書名號、以及 》。 這串連續標點。
  


  

    
      
標記由誰產出意思本頁

    
    
      

        <h-char data-punct>
        refinePunctuation
        標點包裹。token：open／close／end／middle／hangable／consecutive
        
      

      

        <h-layer>
        refinePunctuation
        零寬原子盒，字形溢出蓋在塌縮用的填充上——懸掛就是這麼來的
        
      

      

        data-consecutive-pos
        refinePunctuation
        連續標點串裡的位置（start／inner／end），串的內緣不修剪
        
      

      

        data-followed-by
        refinePunctuation
        可懸掛標點後面那顆的類別，用來補回原子盒打斷的擠壓
        
      

      

        data-followed-by-quote
        markQuoteBoundaries
        這顆標點貼著哪幾層引號邊界，由近而遠——括號在 pseudo 裡，pass 看不到
        
      

      

        q[data-followed-by]
        markQuoteBoundaries
        這個元素的閉括號後面接著可懸掛標點，由 ::after 付那半個字
        
      

      

        <h-iss>
        applyISS
        跨文種混排間隙。data-mode="replace" 表示吃掉了作者的空白
        
      

    
  







  
四、引號邊界

  

    <q> 與 <cite> 的括號來自
    ::before／::after，不在 DOM 裡，所以標點 pass
    在這些接縫上的每個判斷都少算一個字：<q>今天真好。</q>
    渲染成「今天真好。」，句號後面還有一顆 」，它不該懸掛。
    markQuoteBoundaries 只記結構事實，模式判斷留給 CSS。
    關掉「引號邊界修正」就是修正前的樣子。
  

  

    

      
句號收在 q 尾端

      
她停下腳步，說今天真好。

      
    

    

      
開側 ，「

      
她回頭看了一眼，今天真好。然後就走了。

      
    

    

      
外閉側 」、

      
她說今天真好、又補了一句明天也會、就走了。

      
    

    

      
逗號是 last-child，但不在邊界上

      
她想了想，說今天真好，明天也不會差到哪去。

      
    

    

      
空白斷開（縮排也是文字）

      
她停下腳步，說
        今天真好。
      

      
    

    

      
模式即時切換，JS 不重跑

      
他讀的是太陽中文報。那天下午。

      
    

  







  
五、交叉矩陣

  

    q 與 cite 的四種交叉關係，逐格窮舉。標記由頁面從
    實際 DOM 讀出來印，不是寫死的預期值。兩種走訪的規則正好相反：爬祖先
    每經過一層生成器就記一個 token；爬後續碰到生成器就停——它自己的閉括號擋在
    中間。
  


  
巢狀 A > B — 句號一次收兩層

  

    

      
q > q

      
她說他昨天講過今天真好。

      
    

    

      
q > cite

      
她說你該讀讀太陽中文報。

      
    

    

      
cite > q

      
他讀了他說不。整整一夜。

      
    

    

      
cite > cite

      
他讀了太陽中文報社論。

      
    

  


  
直接相鄰 A + B — 兩顆 pseudo 面對面

  

    實測：字體的擠壓跨得過 pseudo 邊界，那條縫本身不需要修理。A 尾端的
    標點只記 close-A——它不記下一個元素的開括號，因為 A 自己的
    」 就畫在中間。
  

  

    

      
q + q

      
她說今天真好。明天也是。

      
    

    

      
q + cite

      
她說今天真好。太陽中文報登了。

      
    

    

      
cite + q

      
他讀太陽中文報今天真好。

      
    

    

      
cite + cite

      
他讀太陽中文報社論兩份。

      
    

  


  
中間夾一顆可懸掛標點 A 、 B

  

    最完整的形狀：同一顆頓號兩側都是 pseudo。前面那顆閉括號由
    A::after 的 letter-spacing 付帳（標記掛在元素上），
    後面那顆開括號由頓號自己把填充換成半個字寬的面孔付帳（標記掛在
    <h-char> 上）。
  

  

    

      
q 、 q

      
她說今天真好、明天也是。

      
    

    

      
q 、 cite

      
她說今天真好、太陽中文報都這麼講。

      
    

    

      
cite 、 q

      
他讀太陽中文報、今天真好。

      
    

    

      
cite 、 cite

      
他讀太陽中文報、社論。

      
    

  


  
中間夾正文 A 然後 B — 對照組，四格應全空

  

    

      
q ~ q

      
她說今天真好然後又說明天也是那天下午。

      
    

    

      
q ~ cite

      
她說今天真好然後翻開太陽中文報那一頁。

      
    

    

      
cite ~ q

      
他讀太陽中文報然後說今天真好那一句。

      
    

    

      
cite ~ cite

      
他讀太陽中文報然後讀社論那一篇。

      
    

  







  
六、把引號關掉

  

    撤銷懸掛的前提是「後面真的有一顆閉括號」，所以每一種「不畫括號」的設定都要
    驗。判詞取 <h-layer> 的 computed display：
    inline-block ＝ 懸掛還在，inline ＝ 被撤銷。這些格子
    各自帶著寫死的設定，不跟控制台走。
  

  

    

      
--han-cite-title-marks: bracket

      
他讀了太陽中文報。

      
    

    

      
--han-cite-title-marks: none

      
他讀了太陽中文報。

      
    

    

      
--han-cite-title-marks: wavy

      
他讀了太陽中文報。

      
    

    

      
--han-semantics: off

      
他讀了太陽中文報。

      
    

    

      
--han-q-quotes: on（預設）

      
她說今天真好。

      
    

    

      
--han-q-quotes: off

      
她說今天真好。

      
    

    

      
zh-Hans 的 “”（非全形）

      
她说今天真好。

      
    

    

      
--han-quotes: none（關不掉）

      
她說今天真好。

      
    

    

      
q { quotes: none }（繞過開關）

      
今天真好。她說。

      
    

  

  

    最後一格是已知限制：直接寫 quotes: none 繞過了變數 API，而
    computed content 對 close-quote 兩種情況都回同一個
    關鍵字，CSS 偵測不到，句末標點會少懸一次。請改用
    --han-q-quotes: off。--han-quotes: none 也不是開關
    ——semantics.css 在 <q> 自己身上又宣告了一次，
    per-element 宣告蓋過繼承，括號照畫。
  







  
七、狀態推導

  

    懸掛不是由模式直接決定的，而是由各語言自己的標點慣例推導出來：排除唯一已知
    置中的 MOE，其餘一律懸掛；zh-Hant 的 off
    再依傳承字形細分。改控制台的「標點慣例」「傳承字形」「語言」看它變。
  

  







  
八、API 用例

  

    每一支都吃 Hyperly（string | Element | Hype）並回傳
    Hype，所以可以自由串接。瀏覽器端會就地改 DOM，SSR 端回傳可序列化的
    結果。
  


  
一次裝好全部

  
import { installFallbacks } from '@hanzi.pro/han.css'

// 瀏覽器：預設整份文件，也可以只給一棵子樹
installFallbacks()
installFallbacks(document.querySelector('main'))

// 依序跑：refinePunctuation → markQuoteBoundaries
//        → applyISSWithProbe → markAdjacentLines
// 大文件自動分塊，沒有節點數上限


  
SSR

  
import { installFallbacks } from '@hanzi.pro/han.css/ssr'
import { html } from 'hyperly/fp'

// SSR 必須明給來源；每一支 pass 都無條件跑，
// 由送達後的 CSS 決定哪些包裹算數
const rendered = html(installFallbacks('<main>…</main>'))


  
只跑標點，模式交給 cascade

  
import { refinePunctuation } from '@hanzi.pro/han.css'

// 讀 --han-punctuation-refinement，再依引擎能力挑配方：
// 宣告 auto ＋ 原生 trim-start ⇒ 只跑懸掛那半
refinePunctuation(document.body)


  
指定模式（本頁第一節用的就是這支）

  
import { refinePunctuationWithMode } from '@hanzi.pro/han.css'

// 不問引擎、不問 cascade，就跑這個模式，
// 並把宣告寫成該元素的行內 --han-punctuation-refinement
refinePunctuationWithMode('compress')(el)


  
只寫 cascade 變數，不動 DOM

  
import { setPunctuationRefinementMode } from '@hanzi.pro/han.css'

setPunctuationRefinementMode('none')(el)


  
引號邊界（跑在標點之後）

  
import { markQuoteBoundaries } from '@hanzi.pro/han.css'

// 標記 <q>／<cite> 邊界上的標點包裹。
// 只記結構事實：括號當下畫不畫，是 CSS 依
// --han-q-quotes／--han-cite-title-marks／:lang() 決定的
markQuoteBoundaries(el)


  
還原

  
import { uninstallFallbacks } from '@hanzi.pro/han.css'

// 拆掉所有包裹、還原被吃掉的空白、清掉全部標記屬性。
// 不需要先裝過，SSR 產出的標記一樣拆得掉
uninstallFallbacks(document.body)


  
自組 pass 集合時要自己分塊

  
import { runPassChunked, refinePunctuation } from '@hanzi.pro/han.css'

// 單支 pass 不會自己分塊；約七千五百個節點以上會爆堆疊，
// 而且是「部分失敗」——半篇排好、半篇沒有
runPassChunked(root, refinePunctuation)







  
九、踩點

  
    
    
  • 
      原子行內盒的起邊被當成行首。把 <q> 或
      <cite> 改成 inline-block（常見於為了
      transform 或裝飾），原生 trim-start 會把它盒內第一顆全形開括號
      削成半形，行中也削，而且不報錯。逐盒解法是
      text-spacing-trim: space-first。
    
    • 
    
  • 
      style query 讀的是容器，不是元素自己。
      --han-q-quotes、--han-cite-title-marks 這類開關
      一律設在祖先上；寫在被它管的元素身上時，該元素的 pseudo 讀不到，
      但它內部的 <h-char> 讀得到——兩半會各說各話。
    
    • 
    
  • 
      覆寫 UA 會自己生成的東西，關掉要明寫。<q> 的引號
      本來就來自 UA 樣式表，撤回自己的宣告只是落回 UA 那份。這是
      --han-q-quotes 的 off 分支必須明寫
      content: none 的原因。
    
    • 
    
  • 
      包裹字符的手法不可以走進 <math>／<svg>。
      MathML Core 的 UA 樣式表給未知後代 display: block，一個
      <h-char> 就把公式拆成兩行；SVG 則根本不畫。兩者整棵跳過，
      交給引擎的 text-spacing-trim。
    
    • 
    
  • 
      比對跨得過元素邊界。底層的文字走訪在攤平後的文字上比對，所以
      <q>…。</q>、 的句號與頓號會被當成同一串連續標點，
      即使畫面上隔著一顆 」。目前只影響連續串內緣修剪的取捨。
