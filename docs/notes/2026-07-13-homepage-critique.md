# 首頁檢討報告——局外人・設計・字體排印三重視角

**日期**：2026-07-13　**對象**：manual 首頁（hero／三大模組／playground／三步即用／footer）
**前提**：可以整個大改，不受現有格局限制。playground 與 hero 演示是既有資產中最強的兩塊，
以下提案均保留其核心、重排其地位。

---

## 一、五秒測試（局外人視角）

進站五秒，訪客能否回答三件事：這是什麼？對我有什麼用？下一步做什麼？

現況答案是「勉強」。hero 一屏塞進了三屏的野心——品牌、七項導航、eyebrow、
三行大標、三行 lede、兩顆 CTA、install chip、四格 stats、右側演示＋五開關＋
放大鏡＋hint 行。右欄的活範文是全站最有說服力的東西，卻被左欄的元素數量稀釋。
訪客的眼睛沒有被引導到「動手玩它」這個唯一重要的動作上。

術語門檻（標點擠壓、著重號）對目標受眾（前端＋排版愛好者）不是問題；
問題是語氣打架——內文是工程語氣，裝飾卻在說拉丁文（TRES MODULI），
英文副標（Semantic Reset／Typography）夾在中間不知道自己是誰。

## 二、誠實性審計（字體排印師最在乎的一節）

**一個排版框架的官網，每一處排版示範都是產品聲明。** 現查出的失實點，
按嚴重度排列：

1. **`npm i han-css` 是錯的套件名**（hero chip ＋ 三步即用×2）。真名是
   `@hanzi.pro/han.css`；`han-css` 是 v3 的名字。訪客照抄會裝到舊版。
2. **「四大書體」「四大模塊開關在握」**（hero lede ＋ eyebrow）——仿宋已下架、
   模組是三個。自家門面數字對不上自家產品。
3. **「混排 0.25em」**（模組III圖說）——CSS Text 4 的 autospace 間隙是
   **1/8 em（0.125em）**，數字錯一倍。
4. **模組III的 BEFORE/AFTER 仍是畫的**（`margin: 0 -0.4em` hack＋上色）——
   hero 剛治好的病，這裡還在犯。
5. **模組I的輸出示意寫死《說文》書名號**——v4 預設 `--han-cite-title-marks: none`，
   示範了非預設行為而不註明，訪客照做會困惑「為什麼我的沒有書名號」。
6. **「2.5k 倉庫星星」**——那是 v3 十年攢的星星，掛在未發布的 v4 首頁上。
   語義上是借貸，遲早被識破。
7. **h1「一 行 引 入」用空格字元排字距**——排版框架的標題用 U+0020 做
   letter-spacing 的活。破壞選取、搜尋、無障礙，且違反自家 copy-style
  （「spacing 是 CSS，永不用空格字元」）。
8. **八個死鏈**——頂欄三個（樣本／術語表／更新記錄→`#`）＋三個「深入了解→`#`」
   ＋三步即用的三個文檔鏈。掛出承諾就要兌現，否則先藏。

## 三、結構檢討（設計視角）

現結構五幕：Hero → 三大模組 → Playground → 三步即用 → Footer。

- **「三步即用」已無存在理由**（你點出的）。playground 的引用碼分頁就是
  「活的 getting started」——按實際配置生成、pm 可切、可複製；「三步即用」的
  npm 分頁是假按鈕、程式碼寫死且用舊 API。整節刪除，殘值（「貼進 head 即完成」
  一句話＋browser support）併入 playground。
- **三大模組是說明書式推銷**。兩張圖仍是畫的（見審計 4、5），而這個產品
  最不缺的就是「真的能演示」的能力。
- **Playground 名為把玩、實為產品核心**（配置→預覽→引用碼），資訊架構上
  應該升格、緊跟 hero，而不是排在第三幕。
- **敘事缺「為什麼」**。ziano 首頁的 #why 是說服層；han 從 what 直接跳到 how。
  不需要 ziano 那麼重——60 字的排版宣言＋一個真 before/after 就夠。

## 四、大改提案：「首頁即範文」

主張一句話：**這個頁面本身就是 han.css 最強的證據**。全站已 dogfood
（字體鏈、變數、真 fallbacks），把這件事從暗線變明線。

### 新結構（四幕）

**0. 頂欄**——保留。死鏈補上或先撤。

**1. Hero＝宣言＋活範文。** 右欄演示原封保留（它是最好的資產），
且**預設全開**（含標點懸掛——首屏就該展示 v4 主打，而不是預設關著）。
左欄瘦身至四件事：h1（CSS 字距）、一句 lede、單一 CTA「打開操場 ↓」、
install chip（改對套件名）。stats 四格改三格誠實數據：支援語種／gzip 體積／
零依賴（一個外部函數庫就寫「1」，也誠實）；星星退場，或標明「v3 legacy」。

**2. 三大模組＝三個真示範。** 每格的插圖改成真 `.han` 塊渲染：
- 模組I（語意）：現有 HTML→輸出的對照保留，但輸出用真渲染；書名號行標注
  「`--han-cite-title-marks: bracket`——一行變數開啟」，把失實點反轉成 API 教學。
- 模組II（字體排印）：已修好（han 變數渲染三大體），不動。
- 模組III（高級排版）：複用 hero 的變數開關技術，hover 或小 toggle 做
  真 before/after；圖說數字改 0.125em。

**3. 操場＝生成器**（第二幕升第三幕、實質主角）。現有配置器已完備；
吸收三步即用的殘值：引用碼分頁下加一行「貼進 `<head>` 即完成」＋
browser support 一句。

**4. 收尾。** 一條 install 行＋GitHub＋**兄弟專案互鏈**（ziano／diantenjeom——
RC 計畫本就要做三站互鏈，收尾是天然位置）＋版本徽章。

刪除：「三步即用」整節（含 getting-started.html/css/i18n 鍵）。

## 五、字體排印細節（大師的挑剔）

- **顯示級**：dogfood 後 display 是 Palatino＋Shanggu Serif——身分對了，
  但 3rem+ 級距下值得 optical 調整：字距 −0.01~0.02em、行高 1.15。
  「印刷品般」四個字必須是版面上最像印刷品的四個字。
- **結構語言二選一**：漢數眉標（壹貳叁）與 MODULE·I／TRES MODULI 羅馬語並置——
  留漢數，羅馬字降為淡色裝飾或刪。
- **圓角語言不一致**：模組區直角美學 vs playground 卡片 `--r-3` 圓角。定一個。
- **hint 行的頓號節奏**（「切換上方功能・立見其變・懸停細處可見其名」）比正文密，
  中黑點用法與正文不同步；改逗號或減為兩段。
- **暗色模式**需全區走查（模組 cream/white 跳色的暗色對應）。
- **RWD** 需專輪走查（hero 雙欄、模組三欄、playground 320px 工具欄）；
  ziano 的 bottom-sheet 經驗可搬。

## 六、行動優先序

| 級 | 內容 | 量級 |
|---|---|---|
| **P0 事實錯誤**（發布前必修） | 套件名×3、四大→三大×2、0.25→0.125em、h1 空格→CSS 字距、死鏈藏或補 | 半小時 |
| **P1 誠實性** | 模組III真演示化、模組I預設註明、stats 誠實化、**刪三步即用** | 一輪 |
| **P2 升格重排** | 四幕結構落地：hero 瘦身＋預設全開、playground 升格、收尾互鏈 | 一次小重構 |
| **P3 打磨** | display 微調、結構語言統一、暗色／RWD 走查 | 隨 P2 收 |

P0＋P1 不動格局、先把「說的」和「做的」對齊；P2 才動結構。
建議順序執行——failing 的誠實性在排版圈是致命傷，格局倒是其次。
