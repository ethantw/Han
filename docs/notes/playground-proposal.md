❯ 如果讓整個首頁就是一個大playground呢，當然也要有演示的說明等等。需要交由Claude Design重新設計嗎？還是照現在的形式改即可？

這個想法我很喜歡——它是「首頁即範文」的邏輯終點：不只是範文，還是可玩的範文。先給判斷，再回答 Claude Design 的問題。

「整頁一個大 playground」值不值得做？

值得，而且 han 是全世界最適合這樣做的產品之一。 理由：han 的產品本質就是「變數一改、排版即變」，那最強的證明就是——你正在讀的這頁隨你撥動而變。撥「標點懸掛」，全頁的行尾標點懸出去；切 MOE→GB，滿頁句號同時跳位；換尚古→源起，整站字形換血。這比任何示意圖都誠實，也天然解決檢討報告裡的誠實性問題（P1 的假圖直接消滅——沒有圖了，全是真的）。

具體形態我會這樣收束：

- 一個常駐配置 rail（sticky 側欄或頂部條），作用域是整個 <main>——不再是小預覽框。rail 自己在 .han 作用域外（chrome 不能被自己的配置弄壞）。
- 章節變成「站」：每節的說明文字同時就是該功能的範文——講著重號的那段自己帶著重號、講注音的那段自己有注音、講擠壓的那段標點特別密。說明即演示，同一段落。
- 引用碼跟人走：玩到哪、配置生成到哪，一個 sticky 的「目前配置」chip 展開就是三分頁生成器。離站時帶走你的配置——這是從 playground 繼承的殺手鐧。
- 護欄：全關的頁面會醜（這很誠實），但要有一鍵「回到預設」；JS 後備全頁重裝的性能要實測（頁面不大，預估可行，不行就按可視區分段重跑）。

代價要說清楚：這是真重構——文案要按「站」重寫（×5 語系，ja/ko 照慣例先墊）、佈局重排，比檢討報告的 P2 更大，但它把 P1＋P2 整個吸收掉了，總帳不虧。

需要 Claude Design 嗎？

不需要重新設計，照現在的形式改即可。 三個理由：

1. 視覺識別已經是 Claude Design 的產出——現在的 token 系統（青翠綠／ivory／ink，方向 B v2）本來就出自 CD。「大 playground」改變的是資訊架構和互動概念，不是視覺方向；識別不動，只是重新編排。
2. 核心資產全部直接復用：configurator 的 intents/apply、codegen、hero 剛做好的變數開關技術——「全頁 playground」工程上＝把配置作用域從小預覽框換成 <main>＋rail 常駐，是移植不是重寫。
3. CD 產出的是靜態 comp，而這個概念的靈魂是互動——用真頁面迭代比對著 comp 實作更快也更真（我們現在就有真字體、真變數、真渲染）。

唯一值得 CD 出手的是單點選型：rail 的形態（左側 sticky？頂部工具條？浮動面板？）可以讓 CD 出兩三個 comp 給你挑。但這也可以我直接做兩個原型讓你在真瀏覽器裡選——我傾向後者。
