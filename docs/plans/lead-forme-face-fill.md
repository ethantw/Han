**狀態**：規劃完成，待實作
**起點 commit**：`3947b1c`（改壞了 revert 到這裡）
**動到**：`manual/public/home/lead-forme.js`、`manual/public/home/lead-forme.css`

## 問題

比對字談字暢的鉛字 logo（`BestOf2015-TypeChat.png`）：它的**字面（printing
face）幾乎填滿字身（em body）**，所以多枚排在一起就是正確的密排。我們的字面
上下左右都留著大片空白，於是鉛字一枚枚相鄰排好，出來的效果**像加了
letter-spacing**。

| | 現在 | 應該 |
|---|---|---|
| 字身 footprint `S` | 90 | 90 |
| 字面 em（`fs`） | **60** ＝ 0.667·S | **90** ＝ 1.00·S |
| 排列間距 `cell` | **94**（比字身大 4） | **90**（字身相接） |
| 實墨寬（尚古明體實測 0.81–0.94em） | 54 | 81–85 |
| 墨佔間距比例 | **57%** | **90%** |

等效死 tracking ＝ `(90−60)/90 + (94−90)/90` ≈ **0.38em**。兩個來源，主項是
`fs`，尾巴是 `cell`；只修一個沒用。

第三個、被前兩個蓋住的問題：`dominant-baseline: central` 把基線放在 hhea
asc/desc 中點 **0.4326em**，但字體的 em 框中心＝實墨中心在 **0.375–0.38em**
（尚古明體實測：上 0.825／下 0.075）。每個字現在**偏高 0.053em**。fs 60 時
是 3.2 單位、看不出來；fs 90 時是 4.8 單位，而每邊餘白只剩 ~5 單位——會把
下緣吃光並撞出上緣。**這是字面填滿的前置條件，不是加分項。**

第四件（獨立需求）：SVG 的 viewBox 左右各留 29.1px 的死空間，來自
`buildForme` 的 `const pad = 34`。要讓 SVG 完整貼合活字版，留白改由
`<figure>` 的 CSS padding 提供。

第五件（獨立需求）：浮雕的**打光順序是反的**。筆畫頂面 `--forme-relief`
（#d6d4cc, 83.9%）比它站立其上的字面 `--forme-face-3`（#f7f5f0, 96.9%）**更
暗**，而筆畫側壁 `--forme-wall`（#e2e0d9, 88.6%）又比筆畫頂面亮。凸起物的
頂面該是最亮的（受光面），側壁才是落影。現在的順序讀起來是**陰刻的拓片**，
恰好是凸起活字的反面。字面一旦填滿，這件事只會更明顯。

## Phase 2 — viewBox 貼合 ＋ CSS padding（純重構）

算式驗過可以做到精確相等，但**驗收不要求零**：目標 0，容許 ≤2px 的位移與
抗鋸齒差異。

**2a `lead-forme.js`**：`pad = 34` → `0`，改發佈 `bleed: 34 / w`。
新的 w ＝ **1286**、h ＝ **882.5**，`bleed` ＝ 34/1286 ＝ **0.026438**。

浮雕預留（`ys.push(p[1] - r, …)`）**保持不動**。`--lf-pad` 量的是「框頂 →
原點 y=0」，那 11 單位包含在裡面；拿掉的話抬升會少 11 單位、整盤下沉
9.4px。代價是上緣仍留 11 單位（相對 882 的高度），那是給字面貼邊的浮雕留的
正當空間。左右、下三邊完全貼合——也就是需求指的那三邊。（上緣要一起貼齊就
多發佈一個 top bleed；11 單位視覺上看不出來，先不做。）

**2b `lead-forme.css`**：`--lf-w` 要解一次閉式，因為 padding 是用它算的。

```
W = C − 2P，P = k·W  ⇒  W = C/(1+2k)

--lf-w: calc(100cqw / (1 + 2 * var(--lf-bleed)));
--lf-pad-css: calc(var(--lf-bleed) * var(--lf-w));
padding: var(--lf-pad-css);
```

1160/1.052876 ＝ **1101.7px**，P ＝ **29.1px**。1286/1101.7 ＝ 1.1673 ≈ 今天
的 1.1672 → **墨的尺寸與位置不變**，這就是能相等的理由。

**2c `--lf-void` 補兩個 `P` 項**（唯一會靜靜位移 17px 的地方）：

```css
--lf-void: calc(
    var(--lf-pad-css)                                   /* ← 新增 */
  + var(--lf-pad) * var(--lf-w)
  + (var(--lf-pad-css) + var(--lf-apex) * var(--lf-w)    /* ← 新增 */
     - (var(--plate-pad) + 30rem)) * 0.5774
);
```

對帳：`29.1 + 0.008554·1101.7 + (29.1 + 0.63033·1101.7 − 516)·0.5774 =
158.4` ＝今天的 158.4 ✓

**2d `--lf-graze` 改鍵在 `cqw`**：`clamp(3rem, 0.1 * var(--lf-w), 8rem)` →
`clamp(3rem, 10cqw, 8rem)`。`--lf-w` 縮了，`0.1·--lf-w` 會變 110.2（今天
116），margin 差 5.8px。`cqw` 本來就是版的量度，不必繞 `--lf-w`。

**2e padding 的連帶**：

- 堆疊版的 `figcaption { margin-inline: var(--plate-pad) }` →
  `calc(var(--plate-pad) - var(--lf-pad-css))`，否則牌記比正文縮進 29px。
- `--lf-air-*` 會全部歸零；`.Controls` 與口袋 `figcaption` 的那兩個 margin
  因此落在 padding box 的內緣——**正好是舊框裡墨的邊界**，位置不變。兩行留
  著（值 0，無害，pad 若復活會自己動起來）。
- 直排分支（`inline-size: min(100%, 620px)`，不在
  `main:not([data-writing='vertical'])` 裡）沒有 `--lf-w` 也沒有 padding →
  會跟著放大 2.6%。要在直排也補同一個 padding。

**驗收**：12 張 diff ≤2px；`marginTop` ≈ −274.4px。

## Phase 3 — 字面填滿

**3a `fs` 併入 `S`**：`GEO.fs` 刪掉，`block()` 用 `S`（90）。字面就是字身那
個方框，不該是第二個數字。

半角「 順便變成實話：`sy = 0.5·S`，而「 自己的 advance 就是 0.5em ＝ 45，
**剛好填滿半個字身**（今天是 30 的字擺在 45 的半身裡）。

**3b 垂直定心改用量出來的 em 中心**：丟掉 `dominant-baseline: central`，改
alphabetic ＋ 在 `m` 的局部座標裡 `y = GEO.emCentre * fs`，`emCentre = 0.38`
（＝sTypoAscender 880/1000）。註解指向
`docs/notes/2026-07-21-svg-glyph-baseline-alignment.md`——同一個兩套 metric
的老問題。

直排標點那一支（`writing-mode: vertical-rl; text-orientation: upright`）走
**橫軸**的同一條規則。破折號那次量到 fs=100 偏 5.25 單位，但**正負號要對
upright Han 重量一次再補**，不猜。

**3c 浮雕 `r` 不動**：11 對舊的 60 em 是 18%，對新的 90 em 是 **12%**——正
好是字談字暢那枚的比例（量它：字 em ≈380px、側壁 ≈45px）。比例自己修好。

**3d 側面規格不動**：`S` 沒變，`lbl-num` 20 / `nm` 8.5 也就不動；字變重之後
數字自己退到後面去。

**驗收**：diff 的非零像素**落在各枚的頂面之內**；字身、側面數字、鉛條、空
鉛、藥丸、牌記、抬升位置不變（`--lf-*` 與 Phase 2 相同——這階段沒動幾何）。
加量：字的實墨框在字面裡**兩軸都居中 1 單位以內**，漢字支與直排標點支各量。

## Phase 4 — 明度（只動浮雕，不動鉛字塊）

`--forme-face-1/2/3` 是**鉛字塊本體**的三個面，需求說了「鉛字塊什麼的都不
變」，所以不碰。明度只修字面上的浮雕兩個 token：

```
--forme-wall    #e2e0d9 → light-dark(#dbd6c9, #26262f)   筆畫側壁（垂直面，落影）
--forme-relief  #d6d4cc → light-dark(#fdfcf9, #4b4b58)   筆畫頂面（水平面，受光）
```

修好之後的明度順序（亮 → 暗）：

| 面 | token | 明色 | 暗色 |
|---|---|---|---|
| 筆畫頂（水平・受光） | `--forme-relief` | **99.0%** | **30.2%** |
| 字面頂（水平） | `--forme-face-3` | 96.9% | 8.2% |
| e1 側壁（垂直） | `--forme-face-2` | 94.5% | 4.7% |
| e2 側壁（垂直） | `--forme-face-1` | 92.5% | 2.0% |
| 筆畫側壁（垂直・落影） | `--forme-wall` | 85.9% | 15.1% |

明色維持「紙上素凸（blind emboss）」的既有語彙——不改風格，只把打光順序轉
正：筆畫頂成為最亮的面（+2pt 高於字面），筆畫側壁 −11pt 於字面，讓那圈落影
band 承擔深度暗示，而不是全靠那條細描邊。暗色本來順序就對（relief > wall >
face），只是把 relief 往上拉 ~9pt 拉開可讀性。

11 層堆疊的擠出**不動**：每層同色無描邊，聯集是一塊平的 WALL 色域，只有外
輪廓有 ≤1 單位的抗鋸齒軟邊，不是糊帶。層數 `k < r` 步進 1 也保證不開縫。

**驗收**：diff 仍落在字面之內；三個 `--forme-face-*` 一個位元都沒動。

## Phase 5 — 密排（無法像素相等，單獨 commit）

`cell: 94` vs 字身 `S: 90` → 每兩枚之間 **4 單位的空無一物**。真鎖緊的版框
鉛塊是相貼的，這 4 單位是無聲的 letter-spacing。改成同一個數之後，兩枚各自
2px 的描邊跨在同一條共用邊上，讀作**一條接縫**——真鉛字盤的樣子。順手刪掉
沒被用到的 `GEO.squeezeGap`。

代價：沿 e2 少 10×4 ＝ 40 單位，w 從 1286 縮到 **1251**（−2.7%），於是同樣
的版寬下**整盤放大 2.7%**，`--lf-ratio`／`--lf-apex`／抬升全部跟著挪。**做
不到像素相等**，所以擺最後、獨立一顆 commit，反悔 revert 一顆即可。

副作用：justify 小鉛塊從 5.9 變 5.6 單位寬，薄薄一片——小鉛塊本來就那樣。

## 風險

**跨行遮擋餘量只剩 2 單位。** `colStep = 153` vs 字身 `H 140` ＋ 浮雕
`r 11` ＝ 151。`buildForme` 那句「每個跨行重疊都穿過鉛條」的畫家排序註解，
是在**字面內縮 15 單位**的前提下成立的；字面填滿之後最高的浮雕點移到字身
自己的頂角再往上 11 單位，正是最危險的角落。

必須逐行比「最高繪製點」與「下一行頂面多邊形」，用 render 驗、不能只算。真
的破了：`leadEm: 0.7 → 0.75`（colStep 157.5）——但那會動到 Phase 5 才准動的
整體比例，發生的話回頭問過再做。
