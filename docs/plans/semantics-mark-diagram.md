# 站① 語意 —— 標記原理圖（SVG）

狀態：提案（2026-07-28）。對象是 `manual/home/station-semantics.html` 的
`<figure class="semantic-elements">`，與 `manual/public/home/station-semantics.css`。
前情：`station-semantics-specimen.md` 第十輪～第十二輪——**文字本身做不出
「偽斜體站直」的過渡**（Chromium 的合成斜體忽略 `oblique <角度>`；直排下
`skewX` 剪切的是整段而非每個字）。這份計畫是那三次撞牆的出口。

---

## 0　定位：為什麼是圖，不是動畫化的文字

前面每一版都在試圖讓**排版輸出自己動起來**，而要動的三件事恰好都不可補間：
合成斜體（離散）、標記的登場（`text-decoration` / 生成內容的幾何）、標記的
斷開。把它們搬到**純幾何**上，限制一次消失——skew、間距、路徑位移全是連續量。

同時它解決了一個一直繞不開的顧慮：**這一站的可信度建立在「你看到的是真的
瀏覽器輸出」**。一組明顯是圖示的長條，不會被誤認成排版輸出；它與詩的關係是
**實物 ／ 原理圖**，不是圖層。分工反而更清楚了。

順帶收掉一個線頭：詩裡的 `p code { display: none }` 讓標籤幽靈目前是啞的。
這張圖接手它們原本的職責——**幽靈說「這叫什麼」，圖說「它會變成什麼」**，
而後者才是本站的論點。那條 `display: none` 因此從未結的線頭變成一個決定。

## 1　形制

**橫排，六條長條，放在詩的旁邊。**

- **橫排是刻意的。** 與直排的詩正交，一眼就知道那不是文字。比同為直排更能
  避開「這是輸出還是你畫的」。
- **放旁邊，不放背後。** 橫排長條疊在直排欄位後面，每一條都會橫穿全部七欄，
  讀起來是七道刪除線——這不是濃度問題，是走向問題，淡色救不了。詩只有
  17em 高，德文信頭以下、`<figcaption>` 以上是整片空地，寬度綽綽有餘。
  （若實作後仍嫌擠，備案是移到帶子下方、`figcaption` 之上，橫貫一整列。）
- **一條 ＝ 一個語意元素 ＝ 一種標記。**

| # | 對應 | `off`（歪的） | `on`（正的） |
|---|---|---|---|
| 1 | 去偽斜體（`<i>`／`<address>`） | 斜、光禿 | 站正，**什麼也沒多** |
| 2 | 專名號 `<u>` | 斜，底下一條**連續**直線橫跨兩段 | 正，直線**從中斷開** |
| 3 | 著重號 `<em>` | 斜、光禿 | 正，底下浮出一排點 |
| 4 | 字重 `<dfn>` | 斜、細 | 正、**變粗** |
| 5 | 書名號甲式 `<cite>` | 斜，底下一條連續直線 | 正，直線變波浪且**斷開** |
| 6 | 書名號乙式 `<cite>` | 斜、光禿 | 正，兩端浮出一對括號形 |

**楷體不畫。** 換字體沒有幾何對應物；用虛線或紋理去代表它，是發明一套讀者
不認識的密碼。六項已經夠滿，留白比湊數好。

第 1 條的職責特別重要：它是 lede 那句「與漢字水火不容的偽斜體，就此告別」
的圖解——**站正本身就是結果，不需要獎品**。其餘五條都是「站正 ＋ 得到一個
標記」，有它作對照，才看得出標記是額外的收穫而不是站正的副作用。

**第 2、5 條的斷開是圖的重點。** 相鄰標記要斷，是單一標本永遠演示不出來的
規則，也正是詩裡特地安排〈美因茲〉〈古騰堡〉與《武經總要》《孫子算經》兩對
相鄰的理由。圖把「為什麼要斷」講成一個動作。

> **甲式波浪的已知落差**：`--han-adjacent-lines-skip-gap-fallback: .125em`
> （4px）小於一個波形週期，所以實物目前兩條波浪讀起來是連的。業主已認領為
> src 的 bug 並將自行修，**本圖照畫斷開**，不等它。記在這裡是為了讓之後看到
> 落差的人知道那是已知的、有主的。

## 2　驅動：一個註冊過的數字，六種幾何

**不要用 `--han-semantics` 的樣式查詢。** 那個旗標是離散的（`on | off`），
而這張圖存在的唯一理由就是「可以連續地動」。改用一個自己的、註冊過的數字：

```css
@property --settle {
  syntax: "<number>";
  inherits: true;
  initial-value: 1;   /* 無 JS ⇒ 無動畫 ⇒ 落在正確的一端 */
}
```

`0` ＝ 歪的、光禿的；`1` ＝ 正的、帶標記。**每一條的每一個幾何量都從它推導**：

| 量 | 寫法 |
|---|---|
| 傾斜 | `transform: skewX(calc((1 - var(--settle)) * -12deg))` |
| 標記浮現 | `opacity: var(--settle)` |
| 斷開 | `translate: calc(var(--settle) * 0.28em)`（只動後半段） |
| 變粗 | `height: calc(var(--bar-h) * (1 + var(--settle) * 0.6))` |
| 波浪畫入 | `stroke-dashoffset: calc((1 - var(--settle)) * var(--len))` |

一個時鐘、六種幾何。比六組 keyframes 好維護，也讓「開關撥到一半」這種狀態
天然成立。

**三個來源，同一個數字：**

1. **入場**：`#station-semantics[data-revealed]` 時，每條 `animation:
   settle 520ms ease-out var(--row-cue) both`，keyframes 只有
   `from { --settle: 0 } to { --settle: 1 }`。
2. **開關**：`#station-semantics:has(input[name='semantics-off']:checked)` →
   `animation: none; --settle: 0`。與詩共用同一個 checkbox，不新增控制項。
   （`animation: none` 是必要的：填充值贏過一般宣告，只重宣告會沒有作用——
   `station-semantics.css` 已經踩過一次。）
3. **`prefers-reduced-motion: reduce`**：不宣告任何 animation，`--settle`
   停在 `initial-value: 1`。

**節拍與詩同步。** 每條長條吃它所對應的那一行詩的 `--row-cue`，於是圖上的
長條與右邊那一欄字**在同一幀改變**。這是整張圖唯一的教學機制——不同步，
它就只是裝飾。

## 3　SVG 的三個坑（先寫下來，免得現場再撞）

1. **`transform-box: fill-box`。** SVG 元素的 CSS transform 預設以
   `view-box` 為原點，六條長條會各自繞著整張圖的原點旋轉。每個
   `<g>` 都要 `transform-box: fill-box; transform-origin: left bottom`
   （下緣左端 ＝ 基線的左端，合成斜體就是繞這裡歪的）。
2. **skew 會連筆畫一起剪切。** 長條本身用 `<rect>` 填色（一塊文字 ＝ 一個
   實心塊，剪切成平行四邊形正是偽斜體的圖示語彙），但**標記不要跟著歪**——
   底線、點、括號屬於「站正之後才有的東西」，應該落在未剪切的座標系裡。
   結構上：`<g data-bar>` 只包 `<rect>`，標記是它的**兄弟**而非子元素。
3. **`vector-effect="non-scaling-stroke"`。** 波浪與底線若用 `stroke`，
   任何縮放都會改變線寬；圖會隨字級 `em` 縮放，所以要釘住。

**座標系**：`viewBox` 用 `0 0 100 <6 條的總高>`，長條寬度統一 100 單位，
一切以 `em` 縮放（`inline-size: 18em` 之類），跟著 figure 的字級走。

## 4　標記的畫法

- **直線／波浪**：兩條獨立的 `<path>`（不是一條 path 兩段），從一開始就是
  兩個元素；`off` 時兩者首尾相接（gap 0），`on` 時後者 `translate` 開一個
  缺口。

  **波浪的幾何寫死，不靠運氣**（示意圖的路徑是我們畫的，所以三件事都能保證）：

  | 量 | 值 | 為什麼 |
  |---|---|---|
  | 週期 | 0.5em | — |
  | 振幅 | 0.09em | — |
  | 切點 | **零交點**，非波峰／波谷 | 切在峰上會露出半個圓弧，讀作被剪壞的 |
  | 每段長度 | **整數個週期** | 兩段長度可以不同，但都要完整 |
  | 相位 | **兩段同相**（都從同方向起波） | 否則讀成兩種波紋，而非同一慣例重複兩次 |
  | gap | 0.3em ＝ **0.6 個週期** | 必須明顯大於半週期，否則圖上也會讀成一條線 |

  > **這是真的甲式做不到的事，要知道自己在畫什麼。** 實物的底線由 run 的
  > 長度生成，而 run 的長度是字數決定的——波形在哪裡被切斷是碰運氣的，
  > 一個五字書名很可能就結束在波峰中間。**圖畫的是慣例應有的樣子，不是任何
  > 實作的輸出。** 對示意圖而言這是對的，但註解裡要寫明，免得日後有人拿圖
  > 對實物、然後認定實作有 bug。
- **著重號的點**：`<circle>` × 6，半徑 0.055em，等距。`on` 時整組
  `opacity: 0 → 1`，並輕微 `translate` 從長條裡「掉」出來 0.06em——比純淡入
  更像「點被標上去」。
- **書名號乙式的括號**：兩個 `<path>`，各是一組雙折線（《 》的簡化形）。
  `on` 時淡入 ＋ 從長條兩端各外推 0.1em，讀作「括號把它框起來」。
- **變粗**：`<rect>` 的 `height` 由 `--settle` 推導，同時 `y` 補償一半，
  讓它**向兩側長胖**而不是向下墜。

## 4b　連帶處理：假 `<code>` 標籤幽靈

圖接手了「哪個標籤換來哪個標記」的職責，原本散在詩裡的 `<code>` 幽靈因此
要收尾。**兩類，分開處理。**

**詩裡那二十幾個 → 刪除。** 它們現在一個像素都不顯示（`p code
{ display: none }`），是純粹的死標記：會隨詩的改寫慢慢對不上，而下一個讀到
這份 HTML 的人得先確認它們還有沒有用。位置更麻煩——
`<u><code>&lt;u&gt;</code>美因茲…</u>` 把外來內容塞在**被展示的元素內部**，
CSS 因此得專門寫規則取消它們身上繼承來的著重號與專名號；**需要寫那種規則
本身就是它們在干擾的證據**。刪掉之後 `station-semantics.css` 裡那整塊
`:is(cite, em, dfn, i, u, var, address) { code { … } }` 也一併消失。

**信頭那兩個 → 保留標示，但搬出 DOM。** 它們是可見的、而且真的在做事
（否則兩塊地址沒有任何東西說明它是 `<address>`）。問題是**標籤名混進了
正文**——實測選取後複製，拿到的是：

```
<address>大宋　京畿路　東京開封府…
<address lang="de">Johannes Gutenberg…
```

一個主張「用對元素、DOM 就是資料」的站，把假標籤字串當成真的文字節點塞進
`<address>` 裡、而且複製得出來，是自打嘴巴。改成資料 ＋ 生成內容：

```html
<address data-tag="&lt;address&gt;">
```
```css
address::before { content: attr(data-tag); }
```

生成內容不進正文、不被複製，標籤名仍然在 HTML 裡當**資料**——對這一站而言
反而更正：元素的身分是資料，不是內容。

**時機：與圖同一批做，不要先刪。** 圖是接手它們職責的東西；先刪會有一段
期間詩裡什麼標示都沒有。刪完之後 `p code { display: none }` 也沒有東西可藏，
一起清掉——那條規則是這個決定僅存的痕跡，留著會誤導人。

## 5　顏色與份量

- 全圖單色，`color-mix(in srgb, var(--palette-accent) 22%, transparent)`
  一級；長條本身可以再淡一階。它是註腳不是主角，**任何時候都不該比詩搶眼**。
- 每條旁邊給一個極小的 `<text>` 標籤（`<u>`、`<em>`、`<dfn>`…），字級
  0.32em、`var(--font-mono)`，與詩裡標籤幽靈同一套視覺語言——這是圖與詩
  之間唯一的明示連結。
- 深色模式：全部走 `--palette-*`，不寫死顏色。

## 6　可及性

- `<svg role="presentation" aria-hidden="true" focusable="false">`。
  它演示的每一件事，右邊的詩都已經用真的語意元素做過一遍了；讓輔助技術讀
  兩遍是噪音。
- 圖裡的 `<text>` 標籤同樣在 `aria-hidden` 之下，不需要額外處理。
- 鍵盤：圖沒有互動；控制它的是既有的 checkbox，本來就可聚焦。

## 7　風險與取捨

- **與信封搶版面**。`figure` 裡已經有一組絕對定位的 `.Envelope` 裝飾。兩組
  互不相干的裝飾同時在場會分散注意。若實作後確實擁擠，優先讓圖**只在開關
  被撥動過之後才浮現**（平時 `opacity: 0`）——它就只在「有人正在玩對照」的
  時候存在，不跟信封打架。
- **圖會不會被當成排版輸出**。橫排 ＋ 純幾何 ＋ 極淡，三者合起來應該夠。
  驗收時找一個沒看過的人問一句「這是什麼」，答案若不是「示意圖」就要調。
- **六條會不會太多**。可以砍到四條（去偽斜體、專名號斷開、著重號、字重），
  甲式與乙式合成一條「書名號」。先做六條，覺得吵再砍——砍比補容易。
- **i18n**：圖裡只有標籤 `<text>` 是英數（`<u>`、`<em>`…），本來就不翻譯。
  這張圖是全站少數不需要 i18n 的東西，算是意外收穫。

## 進度

> **階段 1 完成（2026-07-28）——靜態六條。** `--settle` 尚未接上，六條都畫在
> 落定的一端，先定版面、份量與幾何。
>
> - **版面改成 flex。** 原本 `figure` 是 block、信封絕對定位，圖插進去會疊在
>   詩上。改成 `display: flex; flex-wrap: wrap`，詩與圖並肩，`padding-inline-end:
>   16rem` 替信封留欄——絕對定位以**padding box** 為容器，所以
>   `inset-inline-end: 0` 仍然貼齊 figure 邊緣，不會縮進保留區。
> - **`figcaption` 得自己一行**（`flex: 1 0 100%`）。它同樣是 flex item，
>   放任不管會變成詩旁邊的第三欄，白話註解被擠成四個字寬的絲帶。
> - **`<svg>` 要顯式 `inline-size`。** 有 viewBox 而無 width/height 屬性的
>   `<svg>` 預設 100%×100%，會**蓋過 flex-basis**——`flex: 0 1 20em` 量到的仍是
>   800px。給 `inline-size: 20em; block-size: auto`，讓 viewBox 的比例決定高度。
> - **SVG 幾何屬性的 `px` 不可省。** `y: 75.5` 是無效 CSS（要
>   `<length-percentage>`），整條宣告會被丟掉——字重那條因此一直沒變粗。寫
>   `y: 75.5px; height: 9px`，SVG 裡 1px ＝ 1 user unit。實測 6.5px → 11.7px。
> - **波浪的接縫驗過了。** 把兩段各推回 1.5 單位讓缺口閉合，接縫**看不出來**
>   ——每段 13 個完整週期、起訖都在往上走的零交點，正是為此。
>
> 尺寸定案：長條 5 單位高（字重 9）、圓點 r1.1、缺口 3 單位、波長 5、振幅 0.9。

> **階段 2 完成（2026-07-28）——`--settle` 接上，並改掉一個錯誤的抽象。**
>
> - **長條改成十二格字格**，這是計畫原本寫錯的地方。一整條實心長條 skew 之後
>   只是「一根斜掉的棒子」——而且 5 單位高的長條斜 12°，頂端只位移 1 單位，
>   等於看不見。**合成斜體之所以認得出來，是每個字各自斜而行不動**，只有一排
>   分離的字格說得出這件事。每格繞自己的左下（＝基線原點）剪切，14°。
>   字格 8×10、間距 11、共 12 格。
> - **《》改用 diantenjeom 的真字面**（`Diantenjeom Serif MOE`，繁體語境的
>   慣例分支），不再是我畫的折線。字型已由 `_home.html` 載入，SVG 裡用
>   `text.dtj` 是 `lead-forme.css` 既有的做法。
> - **字重 ＝ 字格變胖**（`scaleX`）。0.28 太胖，字格幾乎併回一條實心長條、

## 第三階段——CD 的 IDC 版（乙）進專案（2026-07-29）

**業主的點子:字格用 IDC**（表意文字描述符 ⿰⿱⿲⿳…）。那是 Unicode 裡專門
**描述漢字結構**的符號,本身不是任何一個字,卻長得像漢字的骨架——既讀得出
「這是漢字文本」,又不可能被誤認成排版輸出。CD 把它們畫成 `<path>` 而非文字,
所以沒有字型依賴、沒有 tofu 風險、也選不起來。

**採用乙（對應詩文），不是甲（隨機）。** 乙的字數與詩逐字相符,連斷點都對:

| 列 | 圖 | 詩 |
|---|---|---|
| `<u>` | 3＋3 | 美因茲＋古騰堡 |
| `<em>` | 5 | 三百枚足矣 |
| `<dfn>` | 3 | 統一碼 |
| `<i>` | 6 | 百萬碼位猶空 |
| `<cite>` 甲式 | 4＋2 | 武經總要＋字驗 |
| `<cite>` 乙式 | 5 | 真實字符論 |

甲是 7/6/7/8/8/6,對應不到任何東西——**裝成資訊的裝飾**。乙讓讀者能真的去數,
圖從「示意」升級成「可驗證」。代價是 `<dfn>` 只有三格、右緣很不齊,但那個不齊
是真的,也正是它讀起來像詩行而非表格的原因。

**CD 有四處比先前的版本更對,值得記下來:**

1. **字格不跟著斜。** 只有 IDC 筆畫斜,方框永遠是正的——「格子是稿紙的,沒有
   引擎弄彎過它」。這才是合成斜體的真實模型:字身框不動,框裡的字被剪切。
   先前整格一起斜是錯的。
2. **`<dfn>` 用 `stroke-width` 0.9→1.7px**,真的變重,不是 `scaleX` 的假胖。
   把字畫成筆畫的唯一紅利。
3. **`<i>` 用 `data-print` / `data-hand` 兩條路徑交叉淡入**——同一個 IDC 結構,
   印刷體與手寫體兩套。楷體是另一種字面,不是較細的字重;先前那個「變細」的
   雙關被這個取代。
4. **`<u>` 的線是鋼灰→綠,其餘標記是純綠。** 因為 `<u>` 的底線在兩態都存在
   (引擎也畫),只有**斷開**是 han.css 的;其餘標記從無到有。顏色因此編碼了
   **出處**,而不只是狀態。

配色的敘事:筆畫歪時鋼灰(引擎的)、扶正時漸變成墨(文本自己的),標記是綠
(han.css 給的)。頂上有圖例。

**新 token**（`variables.css`,兩層結構）:原色 `--color-steel` /
`--color-steel-deep` / `--color-seal` / `--color-seal-bright`;角色名
`--palette-diagram-ink` / `--palette-diagram-ink-off` / `--palette-proof`。
CD 順手把信封那個「唯一刻意的 off-palette 紅」升成原色,信封的
`--_env-frame` 也改指 `--palette-proof`——同一抹紅現在只有一個出處。

### 待修:波浪那一列的顏色說了假話

顏色一旦編碼出處,先前那個簡化就變成一個**主張**了。實測:

| 標記 | off | on | 對嗎 |
|---|---|---|---|
| `<u>` 的線 | 鋼灰 | 綠 | ✓ 引擎也畫底線 |
| 著重號 | opacity 0 | 1 | ✓ 引擎沒有 |
| 書名號乙式 | group opacity 0 | 1 | ✓ 引擎沒有 |
| **甲式波浪** | **綠、opacity 1** | 綠 | ✗ |

引擎**不畫波浪底線**,所以 off 態出現一條綠色的波浪,等於說「瀏覽器給你一條
連著的波浪線」——錯兩次:引擎沒給,而 han.css 給的是斷開的。

這是先前留下的簡化(「甲式的 off 態＝兩段波浪相接」),CD 沿用了。建議改成
**淡入之後再斷開**:綠波先出現(接著的),再拉開缺口。兩件事都是真的——
han.css 既給了波浪,也在相鄰書名之間把它斷開——而且保住了這一列最好看的動作。

### 第四階段——業主的五項調整（2026-07-29）

把 ⿰⿱⿲⿳⿴⿵⿶⿷⿸⿹⿺⿻ 分別排在 Shanggu Serif TC／Shanggu Sans／Songti TC／
PingFang TC／Hiragino Sans,**五支全部用虛線畫**。所以虛線不是風格偏好,
**是這組字元本來的畫法**,實線反而是偏離。附帶紅利:虛線天然讀作「佔位、
示意」,再推遠一點被誤認成排版輸出的風險。`stroke-dasharray: 1.1 0.9`,
user unit,跟著 em 縮放。

**② 波浪缺口 ±4 → ±2**,與專名號同寬。原本的理由是「波浪要比直線更大的
淨空才讀得出斷開」——錯的:波長是 2 單位,4 單位的缺口等於整整少一個週期,
讀起來像被咬掉一口。收到 2,相位在對岸仍乾淨地接續,而那正是把每段寫成
「整數週期、起訖零交點」的用意。

**③ 圖例整條拿掉。** 業主:「完全不知道在幹嘛」。

**④ 14° 標註放大。** 從 2px 的小弧＋5.5px 標籤,改成**把角度畫成面積**:
虛線的直立參考、實線的實際傾斜、兩者之間 15% seal-red 的楔形、8px 粗體標籤。
楔形上下超出該列的字格,所以那條直立參考不會被誤讀成標本的一部分。
位置收在 `<em>` 列自己的帶內(y 47→66),否則會撞到上面 `<u>` 的底線。

**⑤ hover 一列 → 放大 1.14× ＋ 重播該列的動畫。** 對照表本來就邀請人「查一
個」;hover 讓「這個標籤會變成什麼」隨時可以再演一次,而不是只在捲進來後
1.4 秒演一次。三個實作點:

- **每列加一塊透明 `[data-hit]` 板**。字格是 `fill: none`、筆畫是髮絲線,
  沒有它的話一列只有「正好壓在墨上」才 hover 得到,手感像壞掉。板子是每列的
  第一個子元素,所以永遠不會蓋住內容。
- **選擇器是 `[data-mark]:hover`,不是 `:has([data-hit]:hover)`**。`:hover`
  只匹配指標下的元素**與它的祖先**——板子是字形的**兄弟**,字形在上面把
  hover 接走了,板子永遠拿不到。群組是兩者的共同祖先,所以壓在墨上或壓在
  空隙上都會落到它身上。(先寫成 `:has()` 版,實測 `groupHas: false`。)
- **要帶 ID**(`#station-semantics[data-revealed] &`)才壓得過入場那條規則,

只給指標、不給鍵盤:這張圖是 `aria-hidden` 的裝飾,它演示的每一件事旁邊的詩
都用真元素做過一遍;加一個焦點站等於讓鍵盤讀者把同樣的內容過兩遍。

**副作用:字重與虛線互相打架。** `<dfn>` 原本靠 `stroke-width` 0.9→1.7px,
配上虛線之後每一段都變成方塊,整個字淤成一團噪點,不讀作粗。改成
**讓虛線閉合**——間隙 0.9→0.15、線段 1.1→2.5、線寬只加 0.5——落定時幾乎連續
且略粗。這反而更貼題:字重就是「佔位填實成鉛字」,而且與虛線走同一個軸。

**② 缺口再收:4 → 2。** 波長是 4,所以 2 是半個週期——比先前一整個週期
小得多,但仍大於線寬,斷得開。閉合的 translate 同步 ±2 → ±1。
(專名號維持 4:它是直線,沒有週期可言。)

**③ hover 在關閉樣式時,改成預覽「變身後」。** 樣式開著時,hover 重播一個
你已經看過的修正;樣式關掉時,你看的是瀏覽器自己的輸出,這時有意思的問題是
**「它會變成什麼」**——所以 hover 把修正往前跑並用 `both` 停在那裡,指標一
離開,填充值隨動畫一起消失,該列自己掉回引擎的手裡。**同一個手勢,兩種讀法,
而兩者都是「給我看這一列」。**

**④ hover 放大收斂:1.14 → 1.045,`transform-origin` 改 `center center`。**
從左緣長大會讓整列往右撲過去;繞自己的中心只是就地脹一下,那才是「這一個」
該有的手感。

**⑤ 元素名與 IDC 之間的灰色細線(`[data-ledger]`)拿掉。**

**⑥ `<u>` 的上緣與詩的上緣切齊。** 作法不是加一個補償位移,而是把
**`viewBox` 裁到第一列字格開始**(`viewBox="0 24 160 148"`),於是 svg 自己
的上緣就是 `<u>` 列的上緣;`figure` 改 `align-items: flex-start` 即可對齊,
沒有魔術數字要維護——之後挪動列距,對齊會自己跟上。實測兩者的 `top` 都是
249.5px。

實測:關閉樣式 ＋ hover → `--settle: 1`、`scale(1.045)`;移開 → `--settle: 0`。
e2e 五條仍全過。

### 第七階段——14° 只在兩種狀態出現（2026-07-29）

`[data-annotation]` 的透明度綁在 `1 - --settle`,所以**任何**從 0 起跑的動畫
都會讓它閃進閃出——包括 hover 重播。在一列你主動要求再看一次的東西上,每次
都閃一個紅色的校對記號,讀起來像錯誤回報,不像量測。

它只該在兩種狀態出現:**一次性的入場**(它在那裡點名這一站要爭論的缺陷),
以及**關閉樣式**(缺陷就是你正在看的東西)。

分辨的關鍵是 `:not(:has(input[name='semantics-off']:checked))`——關閉樣式時
hover 跑的是同一個動畫,但那時標註**應該**隨著字扶正而淡出,因為那是「缺陷
離開」,不是「一個記號被閃了一下」。

實測:

| 狀態 | annotation opacity |
|---|---|
| 樣式開,靜止 | 0 |
| 樣式開,hover 重播 | **0**（先前會閃到 1） |
| 樣式關,靜止 | 1 |
| 樣式關,hover 預覽中 | 0.61（隨 settle 淡出） |
| 樣式關,預覽落定 | 0 |

### 第八階段——hover-out 的閃現，與波浪的收尾（2026-07-29）

**① hover 移開時 14° 又跑出來——`:hover` 抓不到的一個回程。**

病因在層疊,不在 hover。hover 規則**取代**了那一列的 `animation`;指標離開,
`animation` 復原成入場那條,而**重新套用的入場動畫會從頭跑**——它的
`var(--row-cue)` 延遲期間以 `backwards` 回填 `--settle: 0`。於是整列在回程
悄悄重播了一次,紅色標註跟著閃。任何寫在 `:hover` 上的抑制都救不了:那時候
指標已經走了。

解法是**位置**,不是條件:給標註自己的一次性動畫
(`@keyframes annotation-once`),掛在 `[data-annotation]` 上——**一個 hover
規則從不碰的元素**。它隨入場播一次(`backwards` 讓它在延遲期間就站在歪的那
一列上方),然後永遠停在 `opacity: 0`,旁邊那列重啟幾次都與它無關。

關閉樣式時再把它交還給 `--settle`(`animation: none; opacity: calc(1 - …)`),
所以靜止時在場、hover 預覽時隨字扶正淡出。

實測:

| 狀態 | opacity |
|---|---|
| 樣式開,靜止／hover-in／hover-out ＋80/200/400/700ms | **全部 0** |
| 樣式關,靜止 | 1 |
| 樣式關,hover 預覽中 | 0.51 |

**② 波浪收尾:兩段都跟到 run 的末端。** 業主指出最後一段太短。原因是週期
寫死 4,而 甲式 的 run 是 84 單位——扣掉 2 的缺口剩 82,**除不盡 4**,所以
兩段各短一截(a 40→92 對 run 40→96;b 94→118 對 run 96→124,尾端短 6)。

既然路徑是我們畫的,就反過來解週期:`13p + 2 + 7p = 84` → **p = 4.1**。
於是 a 40→93.3(13 個整週期)、缺口 2、b 95.3→124(7 個整週期),**兩端與
run 齊平**,缺口精確 2,每一段仍是整數個週期、起訖都在往上走的零交點。

e2e 五條仍全過。

### 第九階段——位移的來源，逐項量過（2026-07-29）

**① `<em>` hover 時整列上飄 5.7px——兇手是 `[data-annotation]` 的位置。**
標註當時是 `<em>` 那一列的子元素,而它那條全高的虛線把該列的 `fill-box`
撐成 y 43→166。hover 的 `scale(1.045)` 以 fill-box 的中心為原點,於是原點
落在 y≈104——遠在該列下方——放大就把整列往上推。算式對得上:
`(104 − 51) × 0.045 = 2.4` 單位 ＝ 5.7px。

修法是**位置**,不是數值:把 `<g data-annotation>` 移出 `<em>` 群組,改掛在
`<svg>` 底下當獨立的一組(自帶 `--row-cue: 400ms`)。它本來就跨五列,不屬於
任何一列。實測 hover 位移 5.69px → **0.49px**(只剩縮放本身)。

**② 著重號不再上飄。** 原本 `translate: 0 calc((1 - --settle) * -3px)`
讓點從字裡掉出來。業主指出 `<em>` 與 `<dfn>` 之間本來就有空間,不必上飄——
而且「用移動抵達的標記」暗示文本得讓位給它,實際上不必。改成純粹淡入。

**③ 關樣式時,先剪切、再出角度。** `mark-unsettle` 跑 1→0 時,標註原本
同步淡入。改成從同一個時鐘remap:`--settle` 降到 0.45 以下才開始顯現——
引擎先造成傷害,註記才跟上。

**④ 詩篇:量出來只有兩處會跳,而不是三處。**

| 標記 | 開→關的位移 |
|---|---|
| 專名號底線 | **0**（而且 UA 自己也畫底線,兩態都在） |
| 甲式波浪 | **0**（text-decoration 不佔空間） |
| 著重號 | **帶子寬 347 → 336,少 11px**（直排的著重號坐在字框外,會撐寬行） |
| 書名號乙式《》 | **第七欄長 348 → 312,少 36px**（生成內容佔真的行內空間） |

所以業主點名的三個裡,只有**著重號**真的造成位移。作法:關樣式時把它
**留著、只是不上墨**——`text-emphasis-style` ／ `-position` 照舊,
`-color: transparent`,並在兩態間 transition 顏色。甲式波浪一併比照(它不
造成位移,但這樣才與圖上「off 態沒有波浪」一致)。

**`<u>` 刻意不列入**:實測關樣式時它的 `text-decoration-line` 仍是
`underline`——引擎自己就畫。把它藏起來等於發明一個不存在的瀏覽器。它的兩態
差別在**缺口**,正是旁邊那張圖所主張的。

**踩到的坑**:`text-emphasis: circle under` 是**無效宣告**——`text-emphasis`
的簡寫只含 style 與 color,**position 不在裡面**,所以整條被丟掉(實測
`text-emphasis-style` 仍是 `none`、寬度照樣少 11px)。拆成三條才生效。

**⑤ SVG 的標記也改成用顏色淡入淡出**（業主追加）:著重號的點從
`opacity` 改成 `color-mix(… var(--settle) …)`。整張圖因此只有一種語彙——
**han.css 給文本的東西一律靠「上墨」抵達,不靠移動、也不靠現形。**

**仍未處理,待業主定奪**:書名號乙式的 36px。要補上它得在關樣式時把
《》**畫出來再塗成透明**——那是替瀏覽器畫它從不產生的字元,比 11px 的重排是
更大的一句謊,而且它動到的是 figcaption 那句承諾。已在 CSS 註解裡標明。

### 第十階段——句號、標籤高亮、以及開樣式時的行距抽動（2026-07-29）

**① 詩改成「拉丁二十三字，<em>三百枚足矣。</em>」——句號進 `<em>` 裡。**
用來展示**標點不吃著重號**。先驗過才敢用:Chromium 雖然不支援
`text-emphasis-skip` 這個屬性(`CSS.supports` 回 false),但**預設行為就是跳過
標點**——實測「三百枚足矣。」得到**五個點**,句號沒有。

圖上同步:`<em>` 那列加第六格,裡面放**真的句號**(diantenjeom 字面、實心填色,
不是虛線佔位符),點仍然五個。它跟著整列剪切,因為引擎的合成斜體會吃掉整段
run,標點也不例外。角度參考線隨之右移到 124。

**② 開樣式時 `<em>` 那行的行距先縮後放——`--han-semantics` 的延遲窗口。**
上一輪那組「留著空間、只是不上墨」的宣告寫在**關閉樣式的區塊裡**,所以取消
勾選的瞬間它們就消失了,而 `--han-semantics` 還要再 cue + 520ms 才翻成 `on`
——中間那段時間**兩邊都沒有著重號**,行寬掉了 11px 再彈回來。實測掃描:
`347 → 336（持續約 1s） → 347`。

修法兩層:

- **空間的宣告改成無條件**(移出開關區塊)。空間不可以取決於一個會動畫的旗標;
  han.css 在 `on` 態宣告同樣的值,所以無條件寫是冪等的。
- **墨色交給樣式查詢**`@container style(--han-semantics: off)`。它讀的正是那
  一列身上被動畫的旗標,所以每一行**各自照自己的節拍上墨**,而不是整段一起
  跳。

實測掃描 1.6 秒:**全程 347**。

**③ 標籤語法高亮。** 每個 `<text>` 拆成三段 tspan:角括號用
`--palette-diagram-ink-off`(鋼灰)、標籤名用 `--palette-accent`(綠)。沿用
整張圖既有的雙色語彙——**鋼灰是結構,綠是語意**,而一個標籤讀起來正是
「`<` ＋ 一個決定 ＋ `>`」。

**④ hover 只放大標本,標籤不動、只變深。** 標籤是圖說,不是圖的一部分;
跟著長大就變成整體 zoom,那一列就不再是表格裡的一列了。

實作上這需要**共用的原點**:`[data-bar]`／`[data-rule]`／`[data-dots]`／
`[data-punct]` 是四個不同的盒,用 `fill-box` 會各自繞各自的中心、放大時互相
漂開。改成 `transform-box: view-box` ＋ 每列一個 `--row-mid`,一個座標系、
一個支點,四組一起動。標籤則以顏色回應(`--palette-accent-deep`)。
實測:hover 時標籤寬度 60.66px 不變,標本 `matrix(1.045, …)`。

**⑤ 書名號的 36px 業主結案**:「我要求的是 block axis 不跳就行。」——直排下
那是欄長,不是帶寬,不在要求範圍內。維持現狀,CSS 註解保留說明。

### 第十一階段——三處修正（2026-07-29）

不在任何 `[data-mark]` 裡了,而 `--settle` 正是設在那些元素上;於是它退回

**教訓:把一個元素移出它的資料來源,語意上的歸屬對了,資料流卻斷了。**

**② 句號改用 `Diantenjeom Sans JIS`,並靠基線定位。** 先前用 MOE 分支又

### 第十二階段——開關的極性與歸屬（2026-07-29）

**① 極性反轉:勾選＝開。** 原本是「關掉語意樣式」＋ 勾選＝關,雙重否定;
而 console 的模組開關是 `<input data-cfg-key="semantics" checked>`——**勾選
＝開**。同一頁上兩個控件用相反的慣例本身就是 bug。改成
`<input name="semantics" checked>`,CSS 兩處選擇器改
`:has(input[name='semantics']:not(:checked))`,標籤改「語意樣式——取消勾選,
看瀏覽器的預設」。HTML 預設 `checked`,所以無 JS 時仍落在正確的一端。

**② 是否併入 `<han-console>` 的 semantics 開關——建議不併,理由三條。**

1. **它們演示的不是同一件事,而那個差別正是這一站在教的。**
   console 的開關做的是 `link[data-han-module="semantics"].disabled = true`
   ——**「你沒有 import 這個模組」**,一個交付決策。站①的開關寫的是
   `--han-semantics: off`,那是 han.css **有記載的、按子樹的退出旗標**
   (`semantics.css § Feature Toggles`)——**「你 import 了,但這棵子樹選擇不
   用」**。全站目前只有這裡演示得到第二件事。
2. **作用域不同。** console 是**整頁**;圖與詩的對照是**一個標本**的 A/B。
   整頁翻掉會讓 lede 那句、下方的 `.Papers`、每一站同時變樣,這一站的逐列
   節拍就淹沒在裡面了。
3. **shadow 邊界。** console 的控件在 `attachShadow({ mode: 'open' })` 裡,
   而 `:has()` **穿不過 shadow 邊界**。要連動就得改由 JS 訂閱
   `han-config-change` 再把狀態鏡射到頁面屬性上——把一個純 CSS、無 JS 也能
   運作的機制換成有 JS 依賴的。現在關掉 JS,這個 figure 照樣可用。

**建議的中間路線**:保留本地開關(它是子樹退出的示範、無 JS 可用、作用域正確),
但讓它**不會與 console 相牴觸**——訂閱 `han-config-change`,當 console 把
semantics 模組整頁關掉時,本地開關跟著取消勾選(或直接 `disabled`)。這樣兩者
永遠不會同時宣稱相反的事,而各自的示範都留著。尚未實作,待業主定奪。

### 第十三階段——併入 console，並修掉我自己造成的矛盾（2026-07-29）

**我上一輪的評估是錯的,業主的反駁成立。** 我主張保留本地開關,理由之一是
「它演示 `--han-semantics` 的按子樹退出」;但業主指出 console 一關,美因茲那
行照樣變樣——也就是說**console 本來就作用到這個 figure**,兩個控件重疊而
毫無關係。

量下去發現更糟的:**用 console 關掉 semantics 模組,詩的著重號還在,而且是
滿墨的。**

```
module OFF:  font-style: italic          ✓ 偽斜體回來了
             text-emphasis-style: circle ✗ 點還在
             text-emphasis-color: #0e0e10 ✗ 滿墨
```

那是第九階段那組「留空間」的 CSS 幹的——它是**頁面級**的,模組被卸載之後照樣
畫。**頁面在畫一個函式庫已經不再提供的標記。** 所以兩個開關不只是重複,是
互相矛盾,而矛盾是我造成的。

**改法:**

- 新增 `manual/public/home/module-state.js`——訂閱 `han-config-change`,把
  四個模組的開關狀態鏡射成 `<html>` 上的 `data-han-module-*="off"`。
  必要性在於:**`<link>` 的 `disabled` 對選擇器不可見**,而模組自己的
  `--han-semantics` 旗標又隨著註冊它的那張表一起離開,所以 CSS 沒有任何辦法
  問「han.semantics.css 還在不在 cascade 裡」。
- figure 的本地 checkbox 移除;開關與信封的規則改吃
  `:root[data-han-module-semantics='off']`。
- 留空間的那組宣告**再加一條同樣條件的墨色規則**——`@container
  style(--han-semantics: off)` 只能處理入場那段逐列的旗標動畫,處理不了
  「表被卸載」。

**誠實記下代價**:這個 figure 不再演示 han.css 的**按子樹退出**
(`--han-semantics: off`);console 的開關是「有沒有 import」,是另一種主張。
但本地開關其實從來沒把這個區別傳達給讀者——它只演示了效果。
**一個說實話的控件勝過兩個互相牴觸的。**

實測(切換 console 的 semantics):

| | 模組開 | 模組關 |
|---|---|---|
| `<html>` 屬性 | 無 | `data-han-module-semantics="off"` |
| `text-emphasis-color` | `#0e0e10` | **`transparent`** |
| `font-style` | `normal` | `italic` |
| 帶子寬 | 347 | **347**（不重排） |
| 圖的 `--settle` | 1 | 0 |

切回去全部復原。e2e 五條全過(`module-switches.spec.ts` 那條 lines/squeeze
的失敗是既有的,與此無關)。

**鉛垂線改回 x=110**（業主標的位置）——那是**被標記的那一段結束的地方**（矣的
右緣），不是那一列結束的地方。第六格的句號不吃著重號，所以參考線該立在標記
真正到達的最後一個字上，而不是標點之後。它因此穿過下面幾列較長的格子，這正是
一條鉛垂線該做的事：讓每一列相對於「正」的偏斜都量得出來。

**修正:checkbox 是要「連動」不是「移除」**（業主指正）。站①的 checkbox 復原,
但改成 **console 的代理**,不是自己的控件:

- 標記為 `data-han-module-proxy="semantics"`;
- `module-state.js` 兩向綁定——console 廣播 `han-config-change` 時把代理拉齊

### 第十四階段——把重排移出動畫窗口（2026-07-29）

業主回報連動之後 checkbox 明顯掉幀。量到的原因很直接:**撥動模組＝停用／啟用
一整張樣式表**,`longtask` 觀測到單次 **404–530ms** 的主執行緒阻塞(對照:
只改一個根屬性是 81ms)。它正好砸在圖那 520ms 的修正動畫上。

改法是把便宜的一半和昂貴的一半拆開:

1. `change` 當下**只設 `<html>` 的屬性**——那是圖唯一讀的東西,一次小重排;
2. 動畫照跑;
3. **動畫結束後才去按 console 的按鈕**,樣式表這時才切。

等待時間**從 CSS 讀**(`getComputedStyle($bar).animationDuration`),不在 JS
裡另寫一份 520。

只在**關閉**方向這樣做。開回來時沒有本地動畫要保護:屬性一移除,`--settle`
就交還給入場動畫已填充的 1,沒有正在跑的動畫可打斷。

實測(動畫窗口 0–520ms 之內的最長任務):

| 方向 | 之前 | 之後 |
|---|---|---|
| 關 | **530ms**（就在起手） | **185ms**;657ms 那一下移到 @852,動畫已跑完 |
| 開 | — | 825ms 仍在窗口內(見下) |

**開回來的方向仍會凍一下,這是有意識的取捨。** 要讓它也錯開,就得在「屬性已
移除、模組還沒回來」的空檔裡讓頁面自己畫標記——正是第十三階段修掉的那個錯。
目前兩個方向都變成「一端凍一下」,而不是「動的時候抖」;抖只有在有東西在動的
時候才看得見。

e2e 五條全過。

### 第十五階段——外層改走 `--han-semantics`，不再卸載樣式表（2026-07-29）

延後之後仍偶爾卡。量了兩種機制的成本:

| 機制 | 最長阻塞 |
|---|---|
| `:root { --han-semantics: off }` | **169ms** |
| `link.disabled = true` | 434ms |

**便宜 2.5 倍**,所以 `console-config.js` 的 `applyModules` 對 `semantics`
改走旗標:樣式表始終保持啟用,由 `:root` 的 `--han-semantics` 開關。
其餘三個模組維持原樣。**生成碼不動**——加／減 import 行仍是這個開關要預覽的
決定,只是預覽的手段換了。

**近似的地方只有一處,而且是單向的**:semantics.css 刻意放在
`@container style()` 之外的那幾條(`:root` 的 font-family、
`text-decoration-inset`、`text-underline-offset`——該檔稱之為 correctness fix
而非可退出的加值)在旗標關掉時仍套用,真的沒 import 則會一併消失。已註解。

**過程中發現的障礙**:單獨在 `:root` 設 `off` **沒有效果**——站①的入場動畫
`semantics-settle` 把 `--han-semantics: on` **填在每一列身上**,root 的值傳不
下去。要讓外層的旗標說了算,站內那組 `[data-han-module-semantics='off']` 的
規則必須同時停掉那些動畫——它本來就這麼做,所以兩者接得上;但這條依賴值得記
下來,不然日後有人只改外層會以為壞了。

實測(從站①的代理撥動,含第十四階段的延後):

| 方向 | 第十三階段 | 第十四階段（延後） | 現在 |
|---|---|---|---|
| 關 | 530ms 在動畫上 | 動畫窗口 185ms／之後 657ms | **最長 212ms** |
| 開 | 825ms | 825ms | **174ms** |

狀態全對:`link` 保持啟用、`rootVar: off`、詩回到偽斜體、著重號與波浪透明、
帶子寬 347 不變、`.Papers` 跟著關。

e2e:`mark-diagram` 五條全過;`module-switches` 4/5,唯一的失敗是既有的
lines/squeeze 那條(與 semantics 無關,session 開始時就在)。
