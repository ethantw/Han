## 站①・語意樣式標準化 — LangDemo 四欄

要求全數落點(zh-Hant 欄):著重號 `em`、書名號 `cite`、**雙專名號相連**

### zh-Hant(全要素展示欄)

```html
<article lang="zh-Hant">
  <p><cite>地球無核協議</cite>簽署已屆十五年，最後一批冷戰飛彈的封存磁碟
  卻無人能讀。破譯組成員<u>謝廖沙・林</u>翻查文獻時，讀到一份塵封九十年的
  技術備忘錄——頁首印著<u>蘇聯</u><u>標準委員會</u>的紅色徽章，內容涉及
  一套名為<dfn>KOI-8</dfn>的字元編碼規範。</p>
  <p>所謂<dfn>亂碼</dfn>，是文件以某套對照表寫成——字元各有碼位
  <var>n</var>——卻被另一套對照表強行解讀的結果：正確的數字，對應到
  <em>全然錯誤</em>的文字。彼時的電腦，連<i lang="de">Schrödinger</i>
  這個名字都無法完整顯示。</p>
  <p>人形語言學機器人VELES-7補充：<q>訓練資料不足以令模型辨識這是編碼
  錯誤，而非真實的漢字。</q>換言之，<strong>沒有人讀得懂，是因為所有人
  用的都是錯誤的鑰匙</strong>——正確解讀全程，耗時十七分鐘。彈體內的
  <ruby class="zhuyin">鈽<rt>ㄅㄨˋ</rt></ruby>，下週移送民用儲能工廠。</p>
</article>
```

（HTML 內的換行僅為本文件可讀性；實際落檔時每個 `<p>` 一行、ruby 與標點
貼合，遵 ruby-markup Rule 1。）

## 站貳・鑄字 — 三面對照範文(取代「字字字」)【2026-07-24 新增】

現況:`.Faces` 三格各展一個大「字」(黑/明/楷)。單字細節太少——傳承
字形的差異活在**部件**裡,要一句包含關鍵部件的真文。

### 示例文(≤16 字,台北捷運懷舊題,太陽中文報風)

owner 定調:不用「舊」字,改以世紀入句(2026-07-24 二審)。

**E 案(推薦,16 字):**

> 天梯雖美，台北捷運，戶戶廿一世紀風情

**C 案(16 字):**

> 天梯雖美，台北捷運，戶戶上世紀的風情

世界觀:月球天梯(天柱一號)時代,捷運已是懷舊設施;語料裡
《中央山脈環山軌》已立下「民國一一八年雲林超速捷運通車」的正典,
捷運=上個世紀的老東西,互相咬合。E 案的「廿」正是本報文言數字
家法(卅/廿),且「廿一世紀」=今日讀者自己的年代——你的現在,
是報紙的鄉愁,後設一層。「紀」本身即糹旁,雙關落在「世紀」。

### 部件核對表(E 案)

| 要求部件 | 落字 | 傳承字形看點 |
|---|---|---|
| 英或美 | **美** | 羊頭豎筆與下方撇捺的傳承寫法 |
| 戶 | **戶戶** | 三地三形:傳承戶/陸标户/日戸——疊字連展兩次 |
| 青/情/倩/菁 | **情**(風情) | 青部下方傳承作「円」形,非「月」 |
| 糹旁 | **紀**(世紀) | 糸旁末三筆的傳承寫法 |
| 加映 | **運**(辶旁)、**廿**(古數字) | 辵旁一點與連筆差異;廿字形本身古雅 |

### 版式配套(實作提案)

16 字塞不進現行三格 1:1 大字格。提案:`.Faces` 由三欄改**三列**,
每列=同一句全文(約 `--fs-lede` 級)+右端小標(Hēi/Míng/Kǎi),
Legend 保留;傳承字形開關撥動時三列同步換面,部件差異在同句對照下
一眼可辨。若嫌整句太滿,折衷案:大字格保留但由「字」換成單字輪播
候選「戶/情/紀/美」——傾向前者,整句才有文氣。
