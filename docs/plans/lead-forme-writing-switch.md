# SVG 鉛字：加上直排／橫排 switch

`station②` 的等角鉛字版（`home/lead-forme.js`）目前有「字體」「標點」兩組
radio。加第三組「行向」：**直排（默認）／橫排**。

**已完成**（2026-07-26，commit 9fdda47）。直排輸出與改前逐位元組相同。

實作後補記：

- **標點在兩個方向下看起來一樣，這是對的。**`：「」（）—…` 這類「直排字形＝
  橫排字形轉九十度」的符號，字框轉九十度與字形自身反向轉九十度剛好抵銷——
  相對於行，它們本來就該落在同一個位置。真正會動的是 `、。，` 這種靠**位移**
  而非旋轉取直排字形的符號，以及所有漢字（沒有直排字形，跟著字框轉）。
- **順手修掉一個既有 race**：三個 handler 都閉包了觸發的那顆 radio，換版是
  非同步的，所以動畫途中再點一下，舊的 handler 完成時會套用過期的值，造成
  版面與藥丸不一致。改成讀當下的 `:checked`。連點三組控制項壓力測過。
- **換向耗時 ~4.6 秒**：整盤一起彈起（0.24s），再逐顆落回（0.07s stagger）。
  一開始彈起也做了 stagger，總長 5.6 秒，太拖，改成齊彈。

## 一、關鍵發現：版面幾何完全不用動

一開始以為要把 e1／e2 兩個基向量對調（欄變行），但算過之後——**不用**。

鉛字版是 4×10 的方形字身格子。直排讀「沿 e2 往下走十個、換一欄沿 e1」；
橫排讀「沿 e2 走十個字、換一行沿 e1」。**同一條路徑**。實體上本來就如此：
同樣的字數、同樣的行長，直排橫排排出來就是同一盤鉛字。

鏡像方向也對得上。直排未鏡像時右起，鏡像後首欄在左（現況）；橫排未鏡像時
左起，鏡像後首字在右——螢幕上往左推進，正是 e2（下-左）。所以推進軸兩者
同為 e2、行距軸同為 e1，**連 pitch 都不用換**（推進 `cell` 94、行距
`colStep` 153）。

實測兩種安排的外框：

```
直排（現況）    1286 × 882，空鉛口袋在 右下
軸對調（否決）  1286 × 882，空鉛口袋在 左下   ← 會把角落口袋鏡到另一邊
```

軸對調會把 Controls／figcaption 塞的那個空鉛三角搬到對面，≥80rem 的角落
版位全部要重調。**維持原軸則零影響**：viewBox、painter's order（欄主序＋
跨欄鉛條那條規則）、角落口袋、`--lf-last-slug` 全部照舊。

那麼看得見的差別是什麼？**字面轉九十度**。格子不動、讀法換軸，字就必須跟著
轉——這正是直排橫排在鉛字盤上唯一的實體差異，也讓這個 switch 值得存在。

## 二、實際要改的東西

### 1. 字面矩陣（`block()`）

字面畫在頂面（e1／e2 張成的平面）上。現在：

```
glyph-x → −e1      glyph-y → e2      matrix(−COS, −SIN, −COS, SIN, cx, cy)
```

字的 y（直排的行進方向）落在 e2 ＝ 欄內推進。橫排要讓字的 **x**（橫排的
行進方向）落在 e2，y 落在 e1（＝往下一行）：

```
glyph-x → e2       glyph-y → e1      matrix(−COS, SIN, COS, SIN, cx, cy)
```

行列式兩者皆為 −2·COS·SIN ＜ 0，鏡像性質不變（鉛字反刻是整個梗的根本）。

### 2. 字面書寫模式（`block()`）

```js
const glyphLayout = orient === 'v' && PUNCT.has(char)
  ? 'writing-mode:vertical-rl; text-orientation:upright'
  : 'dominant-baseline:central';
```

直排標點靠 `vertical-rl` 取字體的直排字形（`vert`／`vrt2`）；橫排拿掉，
Diantenjeom 自然給橫排字形——冒號、引號在 em 內的位置就跟著地域公約走。
這是整個 switch 最有內容的一段：同一顆鉛字，直排橫排刻的不是同一個面。

### 3. 擠壓規則（`columnLayout()`）

現在只有 `punct === 'jis'` 才擠 `：「`。改成：

```js
const squeezes = orient === 'h' || punct === 'jis';
```

依你的指示：**橫排下 JIS／MOE／GB 三家都擠 `：「`**。擠壓一旦成立，現有的
邏輯就自動接手——`「` 收成半身、讓出的半身拆成字距小鉛塊平均插進其餘字隙，
所以「第一行會像 JIS 一樣插入字距鉛片」是既有行為的自然結果，不用另外寫。

（附帶效果：橫排時切 JIS／MOE／GB **不改變幾何**，只換字體。現有的 punct
換版動畫照跑，只是 `.col0` 那批其實沒動位——讀起來仍像排版工換掉標點鉛字，
無害，保留。）

半身仍然吃 e2 方向，跟直排同一條 code path；側面刻字（切片編號／字體名／
Diantenjeom）在立面上，不隨行向轉，維持原樣。

### 4. 命名

沿用既有的簡寫風格：radio `name="lf-orient"`，值 `v`／`h`；圖上
`data-orient="v"` 為默認。刻意不叫 `data-writing`——那是整頁預覽用的
（`main[data-writing='vertical']`，lead-forme.css 有規則吃它），兩者互不
相干，名字要分得開。

### 5. 換版動畫

換行向會讓**每一顆字**重刻字面，MOE／GB 下第一行還會重新排。與其挑哪些要
動，不如整盤拆掉重排——這也正是換行向在鉛字房裡的實際意思。

作法：沿用現有 `reslot`，選擇器放寬到 `.Slug`（全部彈出）→ 重建 → 交錯落
回，節奏比照入場（0.07s stagger，全程約 3 秒）。`prefers-reduced-motion`
下直接換，跟現有兩個 switch 一致。

### 6. 標記與文案

`home/station-type.html` 加第三個 `<fieldset>`，並補三個 i18n key（五語）：

- `ltOrientLegend` — 行向／行向／Direction／行方向／<ruby>行向<rt>행향</rt></ruby>
- `ltOrientV` — 直排（默認，`checked`）
- `ltOrientH` — 橫排

`ltControls`（form 的 aria-label）現在寫「字體與標點」，要改成涵蓋三組。

### 7. CSS

預期**零改動**。幾何不變、口袋不變。唯一要看的是三顆藥丸在窄視窗會不會
擠——`.Controls` 本來就 `flex-wrap: wrap`，實測後再說。

## 三、風險與待確認

1. **`：「` 在橫排下三家都擠**——依你的判斷實作。程式碼註解會寫成
   「橫排下 `：` 的尾半空與 `「` 的首半空相鄰，三家公約皆擠壓」，如果理由
   要更精確，講一聲我改措辭。
2. **GB 用 `「」`**——這盤鉛字三家都排 `「」`（國標實務多作 `“”`）。這是
   既有選擇，本次不動，只是提一下。
3. **橫排字形要真的存在**——Diantenjeom 的橫排字形是預設字形，拿掉
   `writing-mode` 就會出現；但 `：` 在三家的橫排位置差異要肉眼確認過才算數。
   實作後我會截三張（JIS／MOE／GB × 橫排）給你看。
4. **字面矩陣的手性**——行列式算過是負的（鏡像保持），但「轉九十度後看起來
   對不對」要眼睛驗收，不是算出來的。第一版就截圖給你。
